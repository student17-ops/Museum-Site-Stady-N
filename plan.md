# План створення сайту Software and Computer Museum

## Контекст

ТЗ (20.10.2026) описує одну сторінку: «Екскурсії, експонати й курси». Це перша сторінка майбутнього сайту музею. Дизайн уже готовий: дизайн-система SCM і макет у Claude Design (посилання є в handoff-файлі). Зараз у папці `сайт музею` лише заглушка `index.html`, ТЗ і handoff. Мета — зібрати сторінку за макетом так, щоб на тих самих компонентах потім можна було додавати нові сторінки.

Сторінка переважно статична. Інтерактивні лише форма запису, перемикач мови UA/EN і меню на смартфоні. Тому: звичайні HTML + CSS + невеликий JS, без фреймворку й збірки.

## Сторінки сайту

| Сторінка | Коли | Примітка |
|---|---|---|
| `index.html` — «Екскурсії, експонати й курси» (8 блоків) | v1, основна робота | Заглушка «Сайт у розробці» лишається, поки сторінка не готова (перейменувати на `coming-soon.html` при запуску) |
| `privacy.html` — політика конфіденційності | v1, **якщо** музей вирішить, що згода потрібна (питання 2) | Текст дає музей / юрист |
| `404.html` | v1 | Проста сторінка в тому ж стилі |
| Сторінка реєстрації на події | пізніше | Залежить від питання 8 (спільна форма чи окрема) |

## Файли

```
сайт музею/
├── index.html              — сторінка: шапка, перший екран, екскурсії, експонати, курси, форма, контакти, підвал
├── 404.html
├── privacy.html            — за потреби
├── assets/
│   ├── css/
│   │   ├── tokens.css      — з дизайн-системи (генерується з tokens.json, руками не правити)
│   │   ├── components.css  — bundle.css з дизайн-системи
│   │   └── page.css        — розкладка сторінки: сітки 3/2/1 колонки, відступи блоків
│   ├── js/
│   │   ├── i18n.js         — перемикач UA/EN без перезавантаження (форма не скидається)
│   │   ├── booking-form.js — перевірка полів, +380 XX XXX XX XX, фокус на перше хибне поле, стани надсилання/успіху/помилки
│   │   ├── booking-links.js — «Записатися» → прокрутка до форми + автозаповнення напряму + aria-live (без плавності за prefers-reduced-motion)
│   │   └── menu.js         — кнопка «Меню» на 768–1279 і на смартфоні
│   ├── i18n/
│   │   ├── uk.json         — усі тексти сторінки
│   │   └── en.json
│   ├── data/
│   │   └── content.json    — картки екскурсій, експонатів, курсів (назви, ціни, тривалість) — щоб замінювати заглушки без правок HTML
│   ├── fonts/              — Handjet, IBM Plex Sans, IBM Plex Mono (SIL OFL, офіційні файли без змін) + OFL.txt
│   └── img/
│       ├── logo.svg        — коли буде файл (питання 7)
│       ├── exhibits/       — фото експонатів (питання 5)
│       └── icons/          — піксельні іконки з дизайн-системи
└── server/
    └── booking endpoint    — приймання заявок; вигляд залежить від питання 1
```

Компоненти беремо з дизайн-системи (`bundle.css`, `bundle.js` → `window.SCM`: `SiteHeader` з `current`, `BookingForm` з `consent` і станом «Не вдалося надіслати», `SiteFooter` з `logo`). Свої значення кольорів і розмірів не вводимо — лише `var(--…)` з `tokens.css`.

## Порядок робіт

**Етап 0. Підготовка (до коду)**
1. Отримати від музею відповіді на питання 1, 2 і 8 — від них залежить форма й сервер.
2. Завантажити з артефакту дизайн-системи `README.md`, `rules.md`, `tokens.*`, `components/bundle.*`, `index.d.ts`; з макета — артборди для звірки.
3. Покласти шрифти локально в `assets/fonts/`.

**Етап 1. Каркас і стилі**
4. `index.html` з восьми порожніх `<section>` з якорями (`#excursions`, `#exhibits`, `#courses`, `#booking`, `#contacts`), `lang="uk"`.
5. Підключити `tokens.css`, `components.css`, написати `page.css` (брейкпоінти 1280 / 768 / 600 за `rules.md`, без горизонтальної прокрутки від 360 px).

**Етап 2. Статичні блоки (з заглушками й бейджем «Заглушка»)**
6. Шапка й підвал (текстовий логотип, навігація-якорі, UA/EN, «Записатися»).
7. Перший екран: назва, слоган, три кнопки-якорі, вікно-термінал і мерехтливий курсор (5 циклів; на смартфоні спрощено).
8. Картки-«вікна»: екскурсії (3), експонати (6, з місцем під «Показати більше»), курси (3) — з `content.json`.
9. Контакти: адреса, години, телефон (`tel:`), заглушка карти + «Прокласти маршрут».

**Етап 3. Інтерактив**
10. `menu.js` — меню на вузьких екранах.
11. `booking-links.js` — «Записатися» → форма з підставленим напрямом.
12. `booking-form.js` — перевірки та всі стани форми (поки що з тестовою відповіддю замість сервера).
13. `i18n.js` + `uk.json` / `en.json` — перемикання мови, збереження вибору, форма не скидається.

**Етап 4. Серверна частина** (після відповіді на питання 1 і 8)
14. Обробник заявок: доставка туди, куди скаже музей (пошта / месенджер / таблиця), захист від спаму, згода (якщо питання 2 = так) і `privacy.html`.

**Етап 5. Перевірка й заміна заглушок**
15. Доступність: контраст, фокус 3 px + 3 px, зони 44×44, клавіатура, читач екрана, `prefers-reduced-motion`.
16. Замінити заглушки реальними матеріалами (питання 3–7), додати англійський переклад, переконатися, що на сторінці немає жодного бейджа «Заглушка».
17. `404.html`, мета-теги, favicon; розмістити на хостингу, `index.html` замінює заглушку.

Етапи 1–3 можна робити паралельно з тим, як музей закриває питання 3–7.

## Що треба від музею

1, 2, 8 — **першими**: адресат заявок, згода на персональні дані, зв'язок зі сторінкою подій. Далі: тип карти, перекладач, реальні фото/ціни/розклад, адреса й телефон, файл логотипа. Ще не вирішено, де буде хостинг сайту — від цього залежить, як робити серверну частину.

## Перевірка

- Відкривати `index.html` у вбудованому браузері на ширинах 360, 390, 768, 1280 px і звіряти з артбордами макета.
- Пройти форму: порожні поля, хибний телефон, успіх, помилка надсилання, перемикання мови із заповненою формою.
- Увімкнути емуляцію «Зменшити рух» — курсор і прокрутка без анімації.
- Пройти сторінку лише клавіатурою; перевірити контраст інструментом.
